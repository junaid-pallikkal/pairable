# Build discipline

- Create only what I asked for. No extra pages, features, files, packages or settings.
- If you have a better idea, suggest it first and wait for my answer.
- Choose the simplest solution that works. Don't overthink.
- Reuse existing components before creating new ones.
- Don't refactor or change code unrelated to the task.
- Ask before installing any new dependency.

## Hackathon mode

- We have 4 hours. A working, demo-ready flow beats perfect code.
- Build the main flow end to end first, then polish.
- Use realistic sample data so the demo looks real.
- Keep the app runnable at all times. Never leave it broken between tasks.
- Work in small steps. Update [TASKS.md](TASKS.md) after each one.
- Empty, loading and error states must exist before the demo.
- Check on a phone-sized screen. Judges often open it on a phone.
